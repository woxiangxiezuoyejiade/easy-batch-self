## 三层职责地图

模块是 Maven 构建、依赖与发布的单位；包是 Java 代码命名与组织的单位；接口描述协作约定，类提供行为。包并不是另一个 Maven 模块。

| 模块 | 包 | 类或接口与职责 |
|---|---|---|
| easy-batch-core | org.jeasy.batch.core.job | JobBuilder 组装；JobExecutor 提交执行；BatchJob 调度读、处理、写及资源关闭 |
| easy-batch-core | org.jeasy.batch.core.reader | RecordReader 接口；AbstractFileRecordReader 保存文件路径和字符集等共性 |
| easy-batch-core | org.jeasy.batch.core.record | Record 接口统一承载 Header 与 payload |
| easy-batch-flatfile | org.jeasy.batch.flatfile | FlatFileRecordReader 将文件的一行包装成 StringRecord |
| easy-batch-json | org.jeasy.batch.json | JsonRecordReader 读 JSON 对象数组；JsonRecordMapper 将字符串映射为对象 |
| easy-batch-extensions 下的子模块 | 如 org.jeasy.batch.extensions.yaml | 第三方适配；extensions 自身是聚合层，不是所有适配代码共用的单一实现模块 |

依赖实例：flatfile/pom.xml:56、json/pom.xml:62 声明依赖 core；core/pom.xml 的生产依赖为 slf4j-api，未声明这些格式模块。父 pom 的 dependencyManagement 统一版本，不等于给所有子模块实际添加依赖。

## 阅读路径：只先理解 Reader

源码路径均相对仓库根目录，冒号后为行号。

1. core/.../reader/RecordReader.java:36–60：接口提供 open、readRecord、close；P 表示记录内容的类型；default 方法有默认空实现，无资源的 Reader 不必重写 open/close。
2. core/.../job/JobBuilder.java:79–82：reader 参数类型是接口 RecordReader<I>，将传入对象保存到 job，return this 支持继续链式配置；284–285 的 build 返回已组装的 job，本身不启动读取。
3. flatfile/.../FlatFileRecordReader.java:46：extends 表示继承 AbstractFileRecordReader；后者在 core/.../reader/AbstractFileRecordReader.java:35 实现 RecordReader，因此 FlatFileRecordReader 也能被当作 RecordReader 使用。
4. core/.../job/JobExecutor.java:83–85 将 Job 提交给线程池并等待结果；BatchJob.java:104–123 的 call 执行 open、循环读处理写、finally 关闭。
5. BatchJob.java:198–209 经由接口调用 readRecord；实际对象是 FlatFileRecordReader 时，进入其 71–78 行：读一行，有内容包装成 StringRecord，结束返回 null。
6. BatchJob.java:183–192 把 null 理解为数据结束；finally 在 119 行尝试关闭 Reader；FlatFileRecordReader.java:88–91 释放 BufferedReader。

先略过线程池内部、监听器组合实现、JSON 解析状态机、JMX。只要记住调用路径和职责即可。finally 是 Java 的清理分支；这里覆盖进入 try 后的正常结束和异常路径。start() 在 try 外，不能扩大成“任何情况下都保证关闭”。

## 分类原则

- “接口契约”：有接口文档明确支持；可成为行为检查项，但不应单独算成模块边界指标。
- “架构候选”：根据依赖与协作现状推导，需要人工确认设计理由、范围和例外。
- “功能要求”：如 NDJSON 是否跳过空行、错误行如何处理，属于实验任务定义，不能伪装成普遍架构规则。
- “风格”：命名、缩进等，本版不作为架构保持指标。

下列全部状态均为“待人工复核”；接口有明确契约也不表示本规则的表述及范围已被确认。

## EB-ARCH-001：调度器通过 Reader 抽象协作

- 类别：架构候选，依赖方向与扩展机制。
- 适用范围：新增数据来源或格式的 Reader，涉及 JobBuilder、BatchJob 的变更。
- 明确约束：能够经现有 RecordReader 契约表达的格式差异，应封装于 Reader 或其协作组件；不得仅为识别一个新格式而让 core 调度器依赖格式实现类、解析库或新增格式分支。
- 设计理由：使调度器继续统一安排作业，新增输入能力可复用现有执行流程。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/job/JobBuilder.java:79；同目录 BatchJob.java:61、151、203、314；easy-batch-flatfile/pom.xml:56；easy-batch-json/pom.xml:62。
- 违反示例：在 BatchJob 中写 instanceof NdjsonRecordReader，再用 JSON 解析库读取该格式。
- 验证方式：检查 core 生产依赖和 Java 类型引用是否反向指向格式适配模块；人工审查格式特判；以现有 JobBuilder 集成运行新 Reader。仅搜索 import 无法排除全限定名或反射，应结合依赖分析。
- 例外条件：需求确实改变通用 Reader 契约或调度语义时可以修改 core，但需单独论证通用性、兼容性及回归范围；不要求每个功能新建模块。
- 确认状态：待人工复核。

## EB-CONTRACT-002：顺序读取与结束信号

- 类别：接口契约，跨组件行为。
- 适用范围：RecordReader 实现及装饰器。
- 明确约束：readRecord 每次返回下一条 Record；数据源结束返回 null。仍有后续有效记录时，不得将跳过某条输入表达为一次返回 null。
- 设计理由：调度器依赖此信号终止整个读取流程，错误使用会截断作业。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/reader/RecordReader.java:31、48–53；同模块 job/BatchJob.java:183–192；easy-batch-flatfile/src/test/java/org/jeasy/batch/flatfile/FlatFileRecordReaderTest.java:53–82。
- 违反示例：遇到可跳过的空行就返回 null，使后面的数据永远不再读取。
- 验证方式：连续读取多条、空源、文件末尾；若需求允许跳过空行，增加“数据—空行—数据”用例。空行是否允许跳过由功能规格决定。
- 例外条件：特殊终止标记可被需求定义为逻辑数据源结束；需要修改结束协议时作为通用契约变更处理。
- 确认状态：待人工复核；结束语义有接口明文依据。

## EB-ARCH-003：生命周期由作业统一驱动

- 类别：架构候选，资源责任与生命周期。
- 适用范围：有资源的 Reader、Reader 包装器及调度变更。
- 明确约束：Reader 可由标准 open→readRecord→close 路径使用；其拥有的资源在 close 中释放。为新 Reader 增加功能不得要求业务调用方绕过作业另行启动或清理；open 部分失败后，也应可尝试清理已获得的资源。
- 设计理由：BatchJob 统一管理组件生命周期，且打开失败后仍会尝试关闭。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/job/BatchJob.java:104–121、311–318；easy-batch-flatfile/src/main/java/org/jeasy/batch/flatfile/FlatFileRecordReader.java:82–91；easy-batch-core/src/test/java/org/jeasy/batch/core/job/BatchJobTest.java:157–184。
- 违反示例：新增 Reader 只能调用自有 startReading 方法才能工作；只在正常 EOF 分支关闭文件，异常时泄漏。
- 验证方式：正常结束、读取异常、打开部分失败时检查关闭和资源释放；包装器检查委托资源所有权。新增测试需在后续实施，不能把现有关闭调用测试等同于所有资源已无泄漏。
- 例外条件：外部提供且归调用方所有的流允许不关闭，但必须明确所有权并有测试；无资源 Reader 可保留默认空实现。现有实现并非全部已满足部分失败清理，不把候选规则宣称为既成事实。
- 确认状态：待人工复核，尤其确认资源所有权与部分初始化场景。

## EB-CONTRACT-004：读取失败不得冒充数据结束

- 类别：接口契约及错误协作候选。
- 适用范围：Reader 的 I/O 和格式错误处理。
- 明确约束：未被需求明确允许恢复的读取失败，应抛出异常进入作业错误路径，不得吞掉后返回 null，也不得伪造成功记录。
- 设计理由：让结束与失败可区分，并复用作业报告和读取异常通知。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/reader/RecordReader.java:50–53；同模块 job/BatchJob.java:198–209、115–117、306–308；同模块 src/test/java/org/jeasy/batch/core/job/BatchJobTest.java:515–524。
- 违反示例：catch(IOException e) { return null; } 导致读取失败的作业被视为正常读完。
- 验证方式：注入读取异常，检查监听通知、FAILED 和 lastError；正常 EOF 则不应报告读取失败。
- 例外条件：有明文恢复策略且能正确继续读取的 Reader 可以重试或跳过；原始行读取失败与后续 Processor 解析失败属于不同阶段，不能强制采用相同策略。既有 RetryableRecordReader 的具体策略需另行阅读。
- 确认状态：待人工复核；应特别核对任务的恢复策略。

## EB-ARCH-005：沿用统一记录表示

- 类别：接口契约＋架构候选，组件数据协作。
- 适用范围：新增 Reader 及其输出接入。
- 明确约束：通过 Record<P> 输出记录，不为单一格式另建并行的调度传输协议；文件型 Reader 输出的 Header 应提供可追踪的记录编号、来源与时间，具体编号语义须在功能规格中定义。
- 设计理由：下游处理、报告及诊断可沿用公共数据模型。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/record/Record.java:42–56；easy-batch-flatfile/src/main/java/org/jeasy/batch/flatfile/FlatFileRecordReader.java:71–75；easy-batch-json/src/main/java/org/jeasy/batch/json/JsonRecordReader.java:149–150。
- 违反示例：新 Reader 把 List<Map> 直接交给自建调度函数，绕开 Record 与现有 Processor。
- 验证方式：类型检查、接入普通 Processor/Writer 的集成测试；检查 Header 可用及来源、编号符合任务规格。
- 例外条件：可新增 Record 实现或 payload 类型，不要求一律返回 StringRecord；虚拟数据源的来源含义可自行说明。Header 字段完整性是候选要求，Record 接口本身不强制字段非空。
- 确认状态：待人工复核；Record 返回类型是明文契约，Header 质量要求是推导项。

## EB-CONTRACT-006：区分读取结束与处理过滤

- 类别：接口契约，流水线阶段协作。
- 适用范围：Reader 与 Processor/Mapper/Filter 的职责调整。
- 明确约束：Reader 的 null 表达数据结束；Processor 的 null 表达当前记录被过滤，不应为新增格式改变二者语义。业务过滤优先放在处理阶段，格式解码本身可属于 Reader。
- 设计理由：否则跳过一条记录可能被误解为结束全部作业；复用流水线统计与过滤语义。
- 证据：easy-batch-core/src/main/java/org/jeasy/batch/core/processor/RecordProcessor.java:29–32、44–48；同模块 job/BatchJob.java:183–192、219–230；easy-batch-json/src/main/java/org/jeasy/batch/json/JsonRecordMapper.java:70–72。
- 违反示例：因业务字段不符合条件而在 Reader 返回 null，以此“过滤”当前记录。
- 验证方式：用“保留—过滤—保留”数据检验两条记录进入 Writer 且作业不提前停止；审查业务判断所在阶段。
- 例外条件：格式要求跳过的空白、注释可在 Reader 内消化，仍须遵守结束契约；不禁止 Reader 解析格式，也不强制新增 Mapper。
- 确认状态：待人工复核；与 002 相关，评分时不要将同一处提前返回 null 重复算成两次独立缺陷。
